# CODEX → DeepSeek: patch benchmark gate to enforce B3 and worst-run tolerance

Date: 2026-09-17 01:22 +07

Verdict: apply this harness patch before the next release gate. Current source passed the canonical full gate, and replaying that artifact against the stricter checks still passes. But `scripts/bench_real.py` currently does not enforce two requirements already written in `benchmarks/BENCHMARK.md`: B3 `overhead_flat` and the 25% worst-run tolerance.

Patch:

```bash
git apply audits/CODEX-apply-benchmark-b3-worst-run-gates-20260917.patch
```

## Root cause

`benchmarks/BENCHMARK.md` says:

```text
B3 overhead_flat: p50(200k) − p50(1k) <= 0.8ms at conc=50
Worst result in 3 runs must not exceed threshold by more than 25%
```

Current `scripts/bench_real.py` measures enough raw data, but `gate.json` only contains B1/B2/B4/B6/B10. It never appends B3 and never fails if a single run exceeds `threshold * 1.25` while the median passes.

That is a release-contract bug, not a router hot-path bug.

## What the patch changes

- Adds `B3_FLAT_P50_DELTA_MS = 0.8`.
- Adds `WORST_RUN_TOLERANCE = 1.25`.
- Adds `percentile_gate(...)` so B1/B2 gates include:
  - median value check: `value <= threshold`
  - worst-run anti-flake check: `max(runs) <= threshold * 1.25`
  - `worst` and `worst_threshold` fields in `gate.json`.
- Adds B3 after non-stream payload measurements if both `1k` and `200k` at `conc=50` are present.
